## Инструменты для работы с LLM: Instructor, Guardrails AI, LangChain

Три библиотеки решают разные задачи и не заменяют, а дополняют друг друга.

### Instructor — структурированный вывод

- Превращает ответы LLM в валидированные Pydantic-модели.
- Автоматически повторяет запрос при ошибке формата.
- Это замена ручного цикла «вызов → ValidationError → повтор с фидбеком».

### Guardrails AI — валидация и безопасность выходов

- Проверяет ответы на соответствие правилам.
- Умеет выбирать стратегию при ошибке: REASK, FIX, FILTER, EXCEPTION.
- Ведёт журнал вызовов, но не управляет контекстом диалога.

### LangChain — память и сжатие контекста

- Единственная из трёх с полноценной системой памяти:
  - буфер истории;
  - скользящее окно последних N сообщений;
  - суммаризация старых сообщений;
  - гибридные схемы.
- Трёхуровневое сжатие контекста: offloading больших данных + суммаризация.
- Долговременная память через LangMem / LangGraph.

### Важные оговорки

- Instructor и Guardrails — stateless: каждый вызов начинается «с чистого листа».
- LangChain — stateful.
- В реальных проектах их комбинируют:
  - Instructor — для структуры ответа;
  - Guardrails — для безопасности;
  - LangChain — для памяти и сжатия контекста.

### Опционально упомянуть

- `json-repair` — локальная починка сломанного JSON без повторного вызова модели.
- Режим Structured Outputs (`strict: true`) у OpenAI — «первый рубеж» защиты
  от ошибок формата.
