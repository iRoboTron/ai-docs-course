# Словарик модуля 6

Термины по алфавиту; названия латиницей — в конце.

## Ложный отказ

> **Ложный отказ** — случай, когда система отказывается отвечать, хотя ответ был верным.

Из [урока 1](chapter-01.md). Плата за строгие проверки; долю таких отказов нужно мерить.

```mermaid
flowchart TD
    A["Ответ верный"] --> B{"Проверка прошла?"}
    B -->|да| C["Ответ гостю"]
    B -->|нет| D["Ложный отказ"]
    style A fill:#1e8449,color:#fff
    style B fill:#1a5276,color:#fff
    style C fill:#1e8449,color:#fff
    style D fill:#7d6608,color:#fff
```

## Подмена инструкций (prompt injection)

> **Подмена инструкций** — вредная команда, спрятанная в данных; модель выполняет её как указание разработчика.

Из [урока 1](chapter-01.md). Защищает не правило в запросе, а проверка ответа кодом.

```mermaid
flowchart TD
    A["Текст со страницы сайта"] --> B["Попадает в запрос как данные"]
    B --> C{"Модель отличает данные от команд?"}
    C -->|нет| D["Выполняет спрятанную команду"]
    C -->|проверка кодом| E["Ответ отвергнут"]
    style A fill:#2d2d2d,color:#fff
    style B fill:#7d6608,color:#fff
    style C fill:#1a5276,color:#fff
    style D fill:#6e2f1a,color:#fff
    style E fill:#1e8449,color:#fff
```

## Проверка чисел

> **Проверка чисел** — правило, по которому все числа из ответа обязаны встречаться в найденных кусках.

Из [урока 1](chapter-01.md). Ловит выдуманные цены и сроки.

```mermaid
flowchart TD
    A["Числа из ответа"] --> B{"Все есть в документах?"}
    B -->|да| C["Ответ можно показать"]
    B -->|нет| D["Отказ: цифра ниоткуда"]
    style A fill:#2d2d2d,color:#fff
    style B fill:#1a5276,color:#fff
    style C fill:#1e8449,color:#fff
    style D fill:#6e2f1a,color:#fff
```

## Прослеживаемость

> **Прослеживаемость** — свойство ответа, при котором видно, на каком месте в документах он основан.

Из [урока 1](chapter-01.md). Даёт и доверие гостя, и возможность проверки кодом.

```mermaid
flowchart TD
    A["Ответ"] --> B["Цитата слово в слово"]
    B --> C["Источник: страница и раздел"]
    C --> D["Можно проверить кодом"]
    style A fill:#2d2d2d,color:#fff
    style B fill:#1a5276,color:#fff
    style C fill:#1a5276,color:#fff
    style D fill:#1e8449,color:#fff
```

## Сверка судьи

> **Сверка судьи** — проверка самого судьи на случаях с известным ответом, до того как ему поручат оценивать всё остальное.

Из [урока 2](chapter-02.md).

```mermaid
flowchart TD
    A["20–30 случаев с известным ответом"] --> B["Судья оценивает"]
    B --> C{"Совпадает с человеком?"}
    C -->|да| D["Можно доверять на выборке"]
    C -->|нет| E["Менять правила судьи"]
    style A fill:#2d2d2d,color:#fff
    style B fill:#1a5276,color:#fff
    style C fill:#1a5276,color:#fff
    style D fill:#1e8449,color:#fff
    style E fill:#6e2f1a,color:#fff
```

## ИИ-судья

> **ИИ-судья** — модель, которой поручили оценить ответ другой модели по чётким правилам.

Из [урока 2](chapter-02.md). Нужен там, где код бессилен: «до пяти вечера» = 17:00.

```mermaid
flowchart TD
    A["Вопрос, ответ бота, факт"] --> B["Судья: ДА или НЕТ"]
    B --> C["Узкий вопрос вместо оценки 1–10"]
    style A fill:#2d2d2d,color:#fff
    style B fill:#1a5276,color:#fff
    style C fill:#1e8449,color:#fff
```
