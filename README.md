# ИИ для документов: от бота для сайта до сервиса для юристов

Практический курс для тех, кто уже программирует (уровень — студент первого курса ИТ-факультета), но почти ничего не знает про ИИ. Цель — к концу курса написать **свой сервис по работе с документами**.

Курс — продолжение школьного курса [«ИИ для 9 класса»](https://github.com/iRoboTron/ai-engineering-school) и переработка интенсива [ai-engineering](https://github.com/iRoboTron/ai-engineering): темы глубже, язык проще, и всё строится вокруг одного продукта.

## Два рубежа

1. **Бот для сайта** — отвечает гостям по документам этого сайта: часы работы, цены, условия, правила.
2. **Сервис для юристов (план-максимум)** — по скачанным законам РФ и документам клиента готовит черновики досудебных претензий, исков и ответов на претензии. Черновик всегда проверяет юрист.

## Как устроен курс: дневник разработки

Курс показывает не готовые решения, а сам процесс разработки. Каждый модуль — очередная версия одной программы:

1. Что сломалось или чего не хватает в текущей версии — живой пример с выводом.
2. Самое простое исправление.
3. Проверка: тест на этот случай, потом замер на наборе вопросов.
4. Если вариантов несколько — сравнение на одних и тех же данных.
5. Решение и почему — запись в журнал решений.

С первого модуля ведутся:

- `cases.jsonl` — каждый пойманный провал становится проверочным случаем;
- тесты `pytest` — гоняются после каждой правки, чтобы новая правка не ломала старое;
- `decisions.md` — журнал решений: «попробовали A, B, C → вот числа → берём B, потому что…».

К первому продукту приходишь, уже перепробовав варианты и сделав выводы сам.

## Программа (черновик)

### Часть 1. Основы в Colab — ничего не нужно ставить

| № | Версия бота | О чём |
|---|---|---|
| 1 | v1: просто спрашивает модель | запрос, роли, токены, цена; первый провал — модель выдумывает |
| 2 | v2: не падает и отвечает в нужном виде | ошибки, повторы, тайм-аут, ответ по схеме, поток |
| 3 | v3: вся справка в запросе | работает на трёх страницах, дорого на тридцати; теряется контекст диалога |
| 4 | v4: простой RAG | документы → текст, нарезка, поиск, «не знаю» решает код |
| 5 | v5: какой RAG выбрать | сравнение нарезок, BM25, эмбеддингов, гибрида, реранкера — выбор в `decisions.md` |
| 6 | v6: цитаты и качество | проверка ссылок кодом, подмена инструкций, эталонный набор, ИИ-судья, знакомство с фреймворками оценки (RAGAS и др.) |

### Часть 2. Бот для сайта — свой репозиторий

| № | О чём |
|---|---|
| 7 | Каркас сервиса: FastAPI, выбранный RAG, хранилище (файл / SQLite / pgvector), тесты в CI |
| 8 | Диалог на сайте: виджет чата, потоковый ответ, память диалога |
| 9 | В работе: журнал, стоимость, кэш, лимиты, резервная модель, переиндексация |
| 10 | Безопасность и выпуск: подмена инструкций, персональные данные, разделение клиентов, деплой |

**Рубеж 1:** бот отвечает гостям на сайте.

### Часть 3. Сервис для юристов

| № | О чём |
|---|---|
| 11 | Корпус законов: скачивание, структура статей, редакции и даты действия |
| 12 | Документы клиента → факты: стороны, даты, суммы, условия; проверка человеком |
| 13 | Генерация претензии и иска: модель пишет доводы, код считает суммы и проверяет каждую ссылку на статью |
| 14 | Процесс с юристом: шаги с подтверждением, версии, выгрузка в DOCX |
| 15 | Качество и ответственность: эталонные дела, «выдуманная статья», «не та редакция», аудит |

**Рубеж 2:** черновик претензии, который юрист проверяет и подписывает.

## Формат

- **Уроки** — объяснение простым языком с примерами; код только короткими фрагментами.
- **Лабораторные** — подробные ноутбуки: шаги от простого к сложному, трассы «что ушло в модель или в поиск и что вернулось», пояснения после каждого шага. Все ноутбуки прогоняются на живой модели.
- **Доступ к моделям** в первой части — через учебный прокси, как в школьном курсе. У своего сервиса — собственный ключ в `.env`.

## Как открыть локально

```bash
cd docs/books && python3 -m http.server 8099 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8099/ — каталог модулей. Читалка собирает модуль в одну страницу.

## Проверка

```bash
python3 scripts/check_project.py      # структура, ссылки, схемы, версия ассетов, ноутбуки
python3 scripts/build_notebooks.py    # собрать .ipynb из notebooks/*.py
```

## Публикация

Сайт: **https://ai-docs.adelfos.ru** — контейнер CT 109 на Proxmox `pxhome`, nginx, статика.

```bash
./deploy-pxhome.sh              # проверки + сборка + выкладка (через ssh-алиас pxhome)
./deploy-pxhome.sh --build-only # только собрать
```

CI: push в `main` запускает проверки на облачном раннере GitHub и выкладку своим
раннером в CT 121 (`.github/workflows/deploy.yml`). Раннер регистрируется один раз:

```bash
./scripts/setup-ci-runner.sh
```

Сертификат и проксирование — общий Nginx Proxy Manager в CT 101: proxy host
`ai-docs.adelfos.ru` → `192.168.0.109:80`, сертификат Let's Encrypt. Поддомены
`*.adelfos.ru` уже указывают на нужный IP, отдельная DNS-запись не нужна.
